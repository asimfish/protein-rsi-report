从策略搜索到可修改的改进程序：RSI 系统调研与设计修订

日期：2026-10-11。本文是下一版方法设计，不是现行 v6 的实现说明或新实验登记。 当前冻结研究继续执行，119 个研究源不改；nAUBC、32+8×16、TrpB4 留出规则和已有负结果不改。本文没有新增模型调用、标签查询或性能结果。

1. 修正研究对象：三层是评价层次，不能替代系统设计

上一版把“在线学习—策略改进—改进器提升”区分开，解决了证明对象混淆，却没有给出第三层的可执行对象、修改接口和学习信号。仅写出 Mφ 更新策略、Q 衡量改进能力，仍不足以成为方法。

下一版应研究：在只有有限、部分科学反馈的条件下，系统能否修改自己的实验策略改进程序，并在同一起点与同样搜索预算下，更可靠地产生有效策略？

部署对象是选择蛋白变体的策略程序；继承对象是生成、检索和搜索这些策略的改进程序。发现一个好策略与得到一个更强的改进程序分开验证。这里的递归是后者能够提出对自身程序的修改，不再增加一个永久固定的第四层 Agent。该思想与 STOP / Hyperagents 有明确先例，不能作为本项目的首创。

CERBERUS 值得借鉴的细节来自作者工件的 knowledge/netlist-dynamic-graph.md 与 headroom-ledger.md：操作反馈按作用条件组织，并将预测与实测的偏差留下来。本文采用其历史组织思想，不把图上的局部响应或其文档中的不确定性描述移植成我们已校准的统计模型。芯片工具可访问设计结构；我们不能访问未测适应度，因此无法照搬其可达改进量的诊断。

Superfiltering 的 IFD 是条件与无条件响应困惑度之比；论文选择低于 1 的较高 IFD 样本。它测量指令对生成响应的帮助，与生物学收益不是同一对象。当前 Qwen 接口也没有在本项目中核验这些困惑度的计算支持。下一版不直接用 IFD 为策略打分，不启动基础模型微调。

另有一项直接相关的反面证据：Gupta 等，EMNLP Findings 2025 在五个基因扰动数据集上，比较了真实与打乱反馈的无工具 BioDiscoveryAgent，发现相近表现；其分子域实验另评价 LLMNN 等方法，不包含这项 BDA 对照。该结论不能扩展为“所有 LLM 都不用反馈”。但它要求我们证明：真实反馈究竟改变了什么行为，是否改善后续结果。

4. 可执行系统：两类可修改程序与固定评测核心

把系统写成任务策略 π 和改进程序 Iφ。φ 表示程序版本及其模块，不表示 Qwen 权重。θ 始终是固定 Qwen3.8-27B。

𝒮 = (π, Iφ)；Iφ = (Rφ, Gφ, Pφ)，θ = θ₀
  • Rφ：经验选择。 输入本次搜索中已完成的匿名对照记录和待处理诊断，输出证据、反例与尚无证据的条件。改的是检索/摘要程序，不能改原始记录。
  • Gφ：修改生成。 输入程序、证据和剩余预算，调用固定模型生成合法代码修改与事前预测。策略修改与改进程序修改使用不同的类型接口，但由同一改进程序组织。
  • Pφ：父代与提案顺序。 在已经评价的开发档案中选择分支和修改对象。它改变搜索顺序，不改总机会数、筛选规则或留出集。

第一版元研究只开放这三个模块；评价预算分配规则先固定。后续若研究可学习预算分配，须作为单独消融，并让所有方法共享逐项费用上限，不能靠多跑候选获益。

固定核心负责标签权限、数值工具、合法性检查、扣费、完整回放、筛选、最终测试和结果统计。提案程序不直接查询标签。代码生成只得到匿名诊断；候选序列和本次已测数据由数值执行器处理。自修改只能写候选版本，不能写评测器、父代历史或当前冻结研究目录。

策略程序可以根据本次已测诊断组合允许的数值算子，决定采集与批次组成；不再只是自然语言建议。每次返回 16 个合法未测候选，由执行器实际执行：

Bt = π(ht; 𝒯)，|Bt| = 16，Dt+1 = Dt ∪ {(x, fτ(x)): x ∈ Bt}，|Dt| = 32 + 16t

h_t 是本次付费观测形成的历史，不假设压缩诊断充分或满足马尔可夫性质。工具集合 𝒯 在各方法间固定；所有程序只能通过该集合使用本次已测标签。内部模型权重不能跨回放继承。固定协议内的确定执行与代码接口需要在新研究中验证，当前 v6 尚未采用这一新处理。

4.1 初始程序与一次修改的执行约定

程序接口拟定如下；这是待实现接口，不能作为已有代码引用。执行器提供共同随机种子，数值算子和必要随机采样在给定种子下可复现；“确定执行”指生成的程序负责实际选点，不保证整个程序搜索完全无随机性。

class Improver:
    def retrieve(self, context, completed_records, limits): ...
    def choose_parent(self, evaluated_archive, search_state): ...
    def propose(self, kind, parent_code, evidence, remaining_budget): ...

def policy(observed_state, numeric_tools, rng):
    # 仅通过受控数值工具取得本回放可用的评分/诊断。
    # 返回16个未测候选；代码生成器不取得这些序列或标签。
    ...

kind 区分策略修改和改进程序修改。提案只返回新代码、修改说明和事前预测；固定驱动器验证执行接口、调用评价并完整追加记录。提案不能自己宣告接受。remaining_budget 是只读费用余额，不能由候选代码重置。返回无效代码、重复提案、失败请求仍占本次修改机会。

具体组合顺序是：固定驱动器先调用 choose_parent，用选定父代及其合法诊断构造检索条件，再调用 retrieve 和 propose；随后由固定核心评价候选、执行预定筛选并追加原始记录。kind=improver 时父代对象为改进程序，评价回调启动受控子搜索，而非让提案模块直接查询标签。第6节的 Iφ(…, U, b) 表示这些可修改模块在固定驱动器中的受控搜索组合；U 的调用、扣费和接受条件归固定核心。驱动器不决定如何检索、生成修改或选择父代。

模块 初始实现 Iφ₀ 一个可由系统提出、随后实测的修改
R：检索 从合法已完成记录中取收益最高/最低各两条；不足则全取，空档案明确无证据 改用诊断距离，再按修改类型分组；同样最多四条，同 token 上限，保留相关反例
G：生成 每次先定位一个可行动问题，提出一项程序修改；输入原始程序和最多四条证据 将“先改采集函数”改为“有排序误差证据先检查代理模型，否则先检查批次重复”；规则与提示构造都形成实际代码差异
P：父代 选择当前正式接受策略；未接受候选保留记录但不作为父代 在已评价档案中加入尚未展开的行为分支，按明确的轮转规则选父代；部署接受规则仍保持固定

三个初始模块及其资源上限须在实现时登记；这张表给出可开发对象，不提供任意增大上下文或多调用的许可。G 中“排序误差”只能在回放已付费标签上做交叉验证，不能使用剩余池真值；缺少证据时返回未知。行为分支的划分规则也只用合法匿名行为摘要。

一次元修改只改变 R/G/P 中一个模块，其余保持相同，先定位哪种修改有效；多个模块的联合修改后续单列。下一次自修改由已经选定的 Iφ′ 生成，固定驱动器只负责权限、预算与评价。这样，“由自身继续修改”落在代码执行上；是否更强仍由第6节的独立效用检验决定。

5. 历史应支持条件性的修改，而不是成功故事

完整记录包括父策略、子策略、改动对象、事前上下文、事前收益预测、共同起点上的实测差值、行为变化、筛选结果和费用。对一对策略，在同一开发起点 ω_j 完整回放后得到：

ei = (ci, πi, π′i, δi, {dij}j, bi, ℓi)；dij = Jτ(π′i, ωj) − Jτ(πi, ωj)

J 仍是原计划的 nAUBC；b_i 是匿名行为差异，ℓ_i 是实际费用。诊断只能来自相应已付费记录。API 失败保留费用，但没有 d_ij，不能记成“该策略有负效应”。多处共同修改只能归因于整项修改，不能把收益分给每个字段。共同起点减少初始样本差异，不保证随机 LLM 输出逐 token 相同。

第一版采用简单的上下文匹配：诊断字段用元训练已测轨迹估计的尺度归一化，按诊断距离、父策略行为与改动类型检索，保留少量支持记录、反例和不同分支。禁止用全候选池适应度统计定义相似性。复杂嵌入检索与额外弱模型不作为默认增加项。

可以研究一个明确的条件收益对象：

g(δ, c) = 𝔼ω[J(π ⊕ δ, ω) − J(π, ω) | c]

这里父策略的结构/行为特征必须包含在 c 中，否则“同一改动”的含义随父策略变化。它是条件平均修改收益，不是从观察轨迹识别的因果效应。新政策选择了旧轨迹没有测过的变体，不能只在旧轨迹上重算奖励冒充新回放。

简单的经验估计可先作排序工具：

ĝ(δ, c) = [∑i∈Heligible wi(δ, c) d̄i] / [∑i∈Heligible wi(δ, c)]

权重非负，来自已定义的匹配规则；无相符记录时返回“未知”，不把零当实测。该估计先在新开发记录上检验误差与收益排序，样本不足时只输出证据列表，不宣称得到校准后验。它不能决定最终接受，更不能把估计均值当实验指标。

对应的机制假设是：检索到与当前问题相关的正负修改证据，能提高下一次有效修改的比例，并最终改善独立部署收益。 “有效修改比例”是诊断；即使比例提升，未提升部署 nAUBC 仍不能称为完成目标。

6. 改进程序如何自修改：递归必须发生在实际程序上

统一改进接口接收修改类型、程序、合法历史、效用回调与预算，输出候选程序以及搜索记录。π 的效用是开发/筛选的任务表现；Iφ 的效用是它在新的子搜索中产生好策略的能力。两者不同，不能用一次策略高分替代元程序评分。

Iφ′ ∈ Iφ(kind = improver, Iφ, Hmeta, Umeta, bmeta)

候选仍须由固定评测核心调用。元修改可以是“由极端收益检索改成上下文检索”“根据完整失败记录改变修改顺序”“从多分支档案选择父代”，而不是换一句泛化提示语后声称程序已经学会学习。源程序与其自修改子代都有可执行版本；下一轮确实由选定子代组织改进。

对一个新子搜索单位 ζ，先重置任务策略为相同 π₀，初始经验为相同 H₀，固定改进程序，在 20 个机会及共同预算内运行：

π̂K,ζ(φ) = Selectdev/screen(SearchK,b(Iφ, π₀, H₀; ζ))，K = 20

Select 不能查看该单位的留出结果；所有搜索链都报告，不能选最好的一条。子搜索中的评价反馈供其自身改进使用，其部署策略选定后在另一块新初始化上评分。

QK,b(φ) = 𝔼ζ,ωconfirm[Jτ(ζ)(π̂K,ζ(φ), ωconfirm) − Jτ(ζ)(π₀, ωconfirm)]

元开发期间，将上式在元训练单位上的经验值定义为 U_meta；其中的“子搜索确认块”一旦反馈给元程序，就整体属于元开发数据，不是论文最终测试。最终元确认使用从未参与选择 φ 的任务/起点，并冻结 φ，禁止在确认期间继续自改。

φm+1 = Selectmeta-dev(φm, φ′m)；ΔQ = QK,b(φnew) − QK,b(φ₀)

这是黑盒、预算约束的程序优化，无需假设对 φ 可微。选择规则固定，也不保证每次真实泛化收益单调上升。只是读入更多历史而程序完全不变，属于记忆积累；得到更好的 π 而 φ 没变，属于策略改进；只有修改了 φ 并在重置后的同预算确认中改善 ΔQ，才支持第三层能力收益。它仍不等于基础模型权重递归增长或一般智能加速。

为隔离“程序更好”与“它读到了更多经验”，主要元比较使用相同 H₀，优先空档案。转移只带 φ 的程序，不带源任务策略、源模型权重或候选标签。之后的“程序旧/新 × 允许经验旧/新”交叉消融单独登记，区分检索程序变化和经验库变化，不偷加免费标签。

7. Superfiltering 思想在这里怎样才算成立

可以低成本筛选的是用于上下文的已完成改进记录，不是未测蛋白，也不是最终策略成绩。确定可排除的包括传输失败、缺失实验结果和重复记录；但要保留其费用与失败类型。效果不显著、负收益的合法修改属于有用反例，不应全删。

如要增加低成本收益预测器，先在合法元训练记录拟合，再对后续开发候选的完整实测配对收益检验：

ρ = Spearman(qi, d̄i)；Recall@m = #{实测正收益且被低成本方法保留} / #{实测正收益}

q_i 是预测分数，不是实测收益。验证时要包含低排名候选，避免只评价保留下来的候选造成验证偏差；所有这类完整评价计入开发费用。排序一致性、正收益召回、费用与最终部署收益一起报告；没有足够正收益时，召回指标记为不可估计。此处固定 m 的选择只能使用开发数据。

第一版仅把这种分数用于历史排序，不硬淘汰未评价的策略候选。其依据是 Superfiltering 的验证逻辑，不是对原算法的复现。若排序与真实收益无关，就移除该筛选模块，不能通过更换效用或反复调筛选比例获得正面结论。

8. 可区分机制的实验，而不是再堆系统组件

所有新实验先登记，共同执行接口、表征、数值工具、初始任务策略、主要指标与逐项预算。模型仍用用户指定 Qwen API；这里的方案不要求额外付费机器或模型训练。

问题 最小实验 主要判断
反馈真的被利用？ 真实历史 / 在同类合法记录间打乱修改—收益对应 / 无效果历史；改动只施加于上下文，私有评测仍用真实标签 提案与实际动作是否改变；独立 nAUBC 是否下降。行为改变本身不足以证明利用有益
条件历史有效？ 无历史 / 极端收益检索 / 上下文检索；记录数、token 上限与查询预算相同 对开发选定策略的冻结测试；历史项被引用不算效果
程序表达比菜单更有效？ 同一固定改进器、配置规则 / 新策略程序；此比较与元层分开 新接口是否有收益空间，不能把接口收益算作自修改收益
档案探索有效？ 当前接受策略单分支 / 多分支开发档案，同机会和回放上限 独立收益；多分支不自动代表不受限的开放进化
元程序真的更强？ 固定原始 Iφ₀ / 冻结改进后的 Iφ₁，各从同一 π₀、H₀ 开始；确认时两者都不自修改 ΔQ 及区间；共同随机外层搜索作为参照
强方法仍可竞争？ 开发选定强固定主动学习、ALDE/SSMuLA 适配方法、共同策略接口下的随机搜索 相同数据协议上的效果与总成本；不能用别篇论文的数值直接比较
是否超出已有反思方法？ 同信息与预算的 GEPA 风格反思优化适配；另对受限 STOP/Hyperagents 元程序适配 若只是现有方法在蛋白任务上的应用，应按应用贡献表述，不包装新基础理论

GEPA、STOP/Hyperagents 的“适配”不是已经复现或已实现的 baseline。其公开方法与本任务的信息权限不同，具体接口和公平预算必须在运行前写清楚。前三类消融用来缩小机制范围，不一次执行整张表；主要元比较固定为新旧 I 的确认，不按结果挑主消融。

确认实验中 nAUBC 仍为主指标；Best@160、费用、失败与回退单列。程序搜索用开发筛选条件，不把反复筛选的置信区间当最终显著性。第9节初版计划针对本次冻结的两个改进程序，各保留五条独立目标策略搜索链；统计考虑这些搜索链与目标初始化的变异。这不是五次独立元开发，只能估计所选程序的条件效用，不能用其区间概括元开发过程的重复性。完整元开发的重复实验及统计另需登记；跨任务结果按任务展示。少数景观不能支持广泛泛化，50 起点不是50蛋白。

9. 实施顺序与真实费用

  1. 现在：完成调研、接口与嵌套评价设计。 这份文档属于该阶段，所有性能状态仍“未实施”。
  2. 现行 v6 完成以后：分析完整动作与反馈记录。 不提前读取中途策略/成绩；先检查策略指导是否改变实际行为、反馈是否对应可行动的诊断。负结果保留。
  3. 新隔离目录：实现共同策略程序接口与固定改进器。 先人工数据验证可执行性和信息权限，再独立代码评审及 distinct fresh 环境实测。未通过不分配真实标签。
  4. 独立开发：比较上下文历史与极端收益历史。 注册新 GB1 初始化，检验条件信息是否有价值；未建立收益就不要默认复杂元程序会解决问题。
  5. 元开发：只修改 R/G/P。 初始限定两轮、每轮两个元程序候选、共四候选机会；全部嵌套子搜索和源模型失败记账。具体开发任务、各单位数量和费用上限需先完成数据审计后登记；这四次不是免费“反思”。
  6. 冻结 φ 后：开展能力确认。 新旧改进程序各五条新子搜索链、相同 π₀/H₀/K 与预算；目标策略也在测试前选定。元确认任务须为没有参与 φ 开发的景观，不能把已经看过的 TrpB4 结果继续当新确认。

可执行预算示例：沿用每链五代×四候选、开发10起点、每代新10筛选起点，则一条策略搜索最多为 10 初始 + 20×10 候选开发 + 5×2×10 筛选 = 310 回放；再对部署策略测50新起点为360回放。两改进器各五链仅一次目标景观确认就最多3,600回放、576,000逻辑标签查询；不含元开发、基线、新景观与额外诊断。所有无效提案仍消耗机会，实际费用可以少于上限，不能把上限冒称已完成。

Ctotal = Cmeta-development + Cpolicy-search + Cconfirmation；b = (Nlabels, Nproposals, Nmodel requests, Ntokens, Tcompute)

K 相同不代表费用相同；各项上限共同约束，失败与校验请求不能隐去。采用确定策略执行时，任务内可能无需 LLM 调用，但它是新共同接口的处理，不能拿这种低成本与现行 v6 混称同一系统。

同预算子搜索的 ΔQ 衡量冻结程序的能力，不自动证明包含元开发费用后的整体成本优势；后者必须另外报告总费用及多次部署时的收益—费用关系。

TrpB4 继续服务于现行冻结协议的正式测试。元开发可用额外已审计景观，最终元确认另留出未用任务；具体数据名单与完整统计计划尚待登记。只在 GB1 新起点上验证元层时，结论必须写为同景观能力，不能声称跨蛋白迁移。

10. 我们能讲的故事，以及不能提前讲的优势

更合理的故事是：科学优化的经验应以“条件—修改—结果”积累；系统不仅复用经验，还尝试修改将经验转化成下一次策略的程序，并独立验证这一改进能力。

预计有价值的特征是：部分反馈下的经验归因、严格科学查询预算内的搜索、任务表现与元能力分离。但它们首先是设计特征与研究问题。程序进化、记忆检索、自修改和多层效用都有先例；若只是拼接这些模块，贡献仍主要是应用系统。只有受控比较证明科学反馈组织的具体作用，才可讨论方法贡献。

当前最值得优先验证的不是“递归一定带来优势”，而是两个机制：给定当前诊断，相关的正负修改记录是否预测下一项改动的收益；修改经验检索/提案程序后，从完全相同的任务起点是否能用同样预算得到更好的策略。 第一项不成立，第三层缺少可学习信号；第二项不成立，最多证明策略搜索或记忆积累，而没有证明改进器能力提高。
